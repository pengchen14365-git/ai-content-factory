AI工具进化论 *2026年3月19日 11:08*

*「Vibe Coding 入门」系列的第 2 篇*

我第一次自己写后端服务的时候，失败了几十次。

不是夸大其词，是真的几十次。报错、重来、再报错、再重来，循环往复。当时整个人都快崩溃了，坐在电脑前盯着屏幕，完全不知道问题出在哪。

不过还好，最后还是蹚过去了。

现在回头看，那段经历其实挺有价值的，因为它让我真正搞懂了一件事：后端为什么这么难入门。

## 前端你能看见，后端你看不见

先说前端。

前端是什么？就是你在浏览器里看到的那些东西。按钮、文字、颜色、布局，你改一行代码，刷新页面，马上就能看到变化。出了问题，你也能直接看到，哪里不对一目了然。

后端不一样。

后端跑在服务器上，没有界面，你看不见它在干什么。你发了一个请求过去，它处理完了，返回一段数据，就这样。整个过程是「黑盒」的。

这就是为什么后端更难理解，因为你没有直接的视觉反馈。出了问题，你得去看日志，去猜，去一点一点排查。对于刚入门的人来说，这个过程真的很折磨。

## 后端到底在干什么

用最简单的方式说，后端就做三件事：

**接收请求 → 处理逻辑 → 返回结果**

比如你在某个 App 里点了「登录」，这个动作就是一个请求，发给了后端。后端收到之后，去数据库里查一下你的账号密码对不对，查完了告诉前端「对了」或者「不对」，这就是返回结果。

数据库是后端的另一个核心概念。你可以把它理解成一张超级大的 Excel 表格，专门用来存数据。用户信息、订单记录、文章内容，全都存在里面。后端的很多工作，本质上就是「读数据库」和「写数据库」。

另一种常见的用法是，调用 API 实现一个特定的功能，然后返回结果。

例如你调用大模型 API，去做翻译、总结。你发给大模型的是提示词，大模型经过处理之后，返回给你结果。

后端服务可以自己写，就像自己下厨做饭；也可以调用别人做好的服务，有点像预制菜。

## 一个真实的后端长什么样

举个最简单的例子，一个「记录访客」的接口。

假设你做了一个网站，想知道每天有多少人来访问。你需要一个后端接口，每次有人打开页面，就往数据库里写一条记录：时间、IP 地址、访问的页面。

这个接口大概长这样：

```
POST /api/visit
接收：{ page: "/home" }
处理：把这条记录写进数据库
返回：{ success: true }
```

就这么简单。前端每次加载页面，就调用一下这个接口，后端收到了，存进去，完事。

你要查「今天来了多少人」，再写一个接口：

```
GET /api/visits?date=2026-03-18
处理：从数据库里查今天的记录
返回：{ count: 128 }
```

这就是后端最基本的形态，接口 + 数据库，来回倒腾数据。

## 有了 AI，后端门槛低多了

我之前失败几十次，主要是 AI 能力还比较弱。

那时候遇到报错，也不知道问题在哪个环节。当时最先好的模型是 Claude 3.5 还是 3.7，但因为不知道如何描述、排查问题，也不知道加日志，整个过程又慢又痛苦。

现在完全不一样了。

你只需要告诉 AI 两件事：

1. **你要存什么数据** ，比如「我要记录每个用户的访问时间和页面路径」
2. **你要处理什么逻辑** ，比如「每次访问就写一条记录，查询时按日期过滤」

AI 会帮你把接口、数据库表结构、甚至部署配置全都写出来。然后再 让 AI 加上详细的日志，排查问题时让 AI 去看日志。

你不需要记住所有语法，不需要背文档，你只需要能描述清楚「我想要什么」。

在与 AI 的协作过程中，你就会慢慢了解后端能力如何调用，知道上面讲的概念具体是什么意思。这个能力，是 Vibe Coding 的核心，也是我们这个系列一直在练的东西。
